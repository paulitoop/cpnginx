# Проверка переносного стенда

Дата: 07.11.2026. Среда: Ubuntu/WSL2, Linux AMD64, Docker Desktop,
Ubuntu 24.04, КриптоПро CSP 5.0.13000, cpnginx 1.22.1,
Vault 1.16.3, Ansible Core 2.19.9. Python-зависимости зафиксированы в
`requirements.lock.txt`, образы и колёса пакетов скачаны локально.

## Выполнено

- Собран локальный Ubuntu-образ с предоставленным дистрибутивом КриптоПро.
- Выпущены свежие ГОСТ УЦ, серверный и клиентский сертификаты, PFX и CRL.
  Старые сертификаты со сроком до 03.07.2026 не используются.
- Подняты два Ubuntu-шлюза и отдельный Vault. Для роли использовались
  сгенерированный inventory и SSH из WSL; контейнер Ansible не создавался.
- Импорт PFX из KV v2 через AppRole, генерация конфигурации и reload прошли
  на обоих шлюзах. Повторный запуск: `changed=0` на обоих шлюзах.
- На свежем втором шлюзе предварительно установлен только публичный клиентский
  сертификат (`PrivateKey Link: No`). Роль импортировала отсутствующий ключ
  из Vault; следующий запуск не повторил импорт.
- Без секрета в Vault роль завершилась ошибкой чтения, без выдачи секрета.
- При неверном PIN импорт завершился ошибкой. Блок `always` удалил созданный
  временный каталог; проверка `/tmp/cpnginx-pfx-*` не нашла остатков.
- Дубликаты имён интеграций отклонены до изменения узлов: `changed=0`.
- Пустой каталог интеграций удалил управляемые `.conf` на обоих узлах.
  Повторное применение пустого набора: `changed=0`.
- Восстановление YAML вернуло конфигурацию, следующий запуск снова дал
  `changed=0` на обоих узлах без повторного импорта ключей.
- Проверены 9 модульных тестов роли и 6 тестов lab, синтаксис playbook,
  Python, Bash, YAML и `git diff --check`.
- Тестовые PIN, AppRole и Vault root token не найдены в выводе Ansible
  и файлах, подготовленных к публикации. Приватные данные находятся вне Git.
- Повторная подготовка скачала опубликованные роли с GitHub. Обычный
  `configure` получил commit `0770a35` из `main`; пустой `integrations/demo`
  удалил конфигурации. `configure --cached` использовал тот же commit и дал
  `changed=0` на обоих узлах. Для испытаний PFX применялся явно заданный
  приватный локальный каталог с тестовым YAML; его в Git не публиковали.
- Перезапущенный одноразовый контейнер успешно использовал свежую CPSD
  от пользователя `lab` с доступом через группу `lab-rng`.

## Сквозные испытания 08.11.2026

Новый предоставленный владельцем ключ принят CSP. Тип: `TLS Server`, срок:
`permanent`, `Restrictions: 0`. Ключ хранится только в приватном локальном
`server.license`; ни значение, ни его фрагменты в Git не включены.
Ранее использовавшийся ключ старого сервера проверен отдельно и отклонён
как `License expired or not yet valid`; новое значение устранило блокировку.

При включении строгой проверки цепочки обнаружены и исправлены две ошибки
первоначальной сборки lab:

- Для тестового УЦ заданы ключ подписи и KeyUsage `digitalSignature`,
  `keyCertSign`, `cRLSign` (134). Прежний УЦ не имел прав подписи сертификатов
  и CRL, из-за чего проверка TLS завершалась `0x80090349`.
- Включён уровень `info` журнала Nginx. Сообщение об отсутствии клиентского
  сертификата относится к этому уровню и необходимо для подтверждения
  причины отрицательного теста.

Подтверждено:

- [x] Контрольный ГОСТ TLS с проверкой серверного сертификата проходит.
- [x] Без клиентского ключа mTLS возвращает HTTP 400; сервер фиксирует новое
  сообщение `client sent no required SSL certificate`. Произвольная ошибка
  handshake не принимается за успешный отрицательный тест.
- [x] После загрузки PFX в Vault и конфигурирования защищённая страница
  возвращается через один шлюз и через каждый из двух шлюзов (HTTP 200).
- [x] Весь процесс повторён после `reset-demo`: 0/2 доступных прокси до
  загрузки PFX, 2/2 после настройки. Повторный Ansible-прогон: `changed=0`
  на обоих шлюзах.
- [x] Для сквозного прогона YAML получен из временной ветки GitHub, commit
  `0d8fadd8ed8f9d2f6ba86a1f386cfa1e321dd6f1`. Ветка содержала только
  синтетическое описание интеграции, без PFX, PIN или лицензии.
- [x] Переключение с двух узлов на один удаляет только второй шлюз;
  защищённая страница через оставшийся шлюз доступна.
- [x] Из Windows через HTTP доступны проксированная защищённая страница и
  интерфейс Vault. Проверка выполнена Windows curl, не браузером.
- [x] Повторный `reset-demo` проверен с одним шлюзом: возвращено исходное
  состояние без клиентского PFX. Исходные файлы подготовки сохранены.

Остаётся вручную проверить демонстрацию в Windows-браузере после добавления
hosts и доверия новому тестовому УЦ. Windows hosts и хранилище доверия
автоматически не изменялись. Это требуется для прямых ссылок HTTPS;
HTTP-ссылка через локальный прокси не требует ГОСТ в браузере.

Отдельный сценарий Molecule не запускался: он требует собственных
сертификатов, Vault и подготовленного образа. Его наличие не означает,
что он прошёл. Роль установки проверена синтаксически; установка пакетов
проверялась через Dockerfile, а не отдельным прогоном роли на чистой VM.
Измерения эффективности из старой VM-версии к этому Docker lab не относятся.
